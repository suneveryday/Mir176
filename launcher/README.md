# 独立 Windows 登录器

`Mir176Launcher.exe` 是独立的 Windows 程序。它只管理本机客户端的连接设置并启动游戏，不包含完整客户端、素材、账号认证、服务端或自动更新器。Release另提供不含资源的Client-Program包，其中已包含此登录器；游戏源码、程序和完整资源包由独立私有项目 [Mir176Client](https://github.com/suneveryday/Mir176Client) 交付。完整组装步骤见 [分模块交付](../docs/DISTRIBUTION.md)。

## 使用

1. 将登录器放到完整客户端目录，和 `Mir2Classic176.exe` 同级；保持原有 Map、Resource、Wav 等资源。
2. 双击登录器，填写服务提供者给出的 IPv4 地址或域名，以及登录端口，再点“开始游戏”。默认端口7000可修改；首次地址为空，不附带现用地址。
3. 游戏账号、密码仍在游戏窗口中输入。后续启动会读取本地配置，也可先点“保存设置”。改服务器前正常退出当前客户端并等待保存。

地址最长30个ASCII字符，来源于现有客户端的启动结构限制；本登录器不接受IPv6字面量、网址或地址中附带端口。设置仅写入客户端旁的 `Mir2Classic176.ini`，保留原有画面、资源、注释及其他配置；无BOM按现有游戏的CP936读取，CP936/UTF-16LE保留原编码；带BOM的UTF-8转为Windows INI接口可读的UTF-16LE，保留文字内容。重复Server分节/字段会拒绝保存，不猜测采用哪一项。写入使用同目录临时文件与原子替换，不写账号密码。

该目录的游戏已运行时，登录器拒绝改地址或再次启动。启动目标固定为同目录游戏EXE、工作目录固定为客户端目录，不发送旧编码启动参数或调用命令Shell。保存设置可以独立于启动执行。

## 服务端配套

游戏客户端从本地 INI 读取连接地址和端口。当前配套为游戏客户端 0.1.5、Docker 服务端 0.1.4。

登录地址只负责连接登录入口。选角/游戏网关仍按服务端下发地址连接；管理员须用Docker包配置器填写玩家可达的地址与登录、选角、游戏端口，并正确配置路由和防火墙。填写登录器不能覆盖服务端发错的重定向地址。不同服务器的账号和角色由各自服务端保存，登录器不迁移任何角色。

## 构建与验证

Windows使用系统官方.NET Framework C#编译器：

```powershell
launcher/build-on-windows.ps1 -OutputDirectory .build/launcher
tests/launcher/run-windows.ps1 -OutputDirectory .build/launcher-tests
```

在完整仓库根目录运行，测试目录必须为全新隔离目录。测试验证地址/端口边界、编码与配置保留、阻止重写运行中客户端、按钮流程和实际本地桩程序启动，不连接游戏或修改真实角色。GitHub Windows CI执行相同构建和测试。实际私有连接、用户安装目录和原始日志不进入Git或Release。
